# Homologação v1.0.0-rc.13

> **Data:** 09/11/2026 · **Ambiente:** homologação (`master`, Cloud Run `saude-monitor-backend-hom`, banco `saude_monitor_hom`)
> **Rc anterior:** [`v1.0.0-rc.12`](./v1.0.0-rc.12.md) (09/11/2026) · **Origem:** `develop` no merge do PR #247
> **Responsável pela validação:** Gabriel Vogado (PO)

Esta rc leva a correção do teste do rate limit (M-072). O teste do teto por IP falhou no CI do
PR de promoção da rc.12 porque as chamadas atravessaram a virada da janela fixa de 1 minuto. O
`RateLimitService` passa a receber o relógio pelo construtor, e os testes usam um relógio parado.
O comportamento do backend em produção é o mesmo: o construtor que o Spring usa continua com o
relógio do sistema. O app sai igual ao da rc.12.

O roteiro da rc.12 ainda não foi preenchido. A rc.13 contém tudo da rc.12, então a seção 3
remete ao roteiro da rc.12 inteiro. A candidata à `release/1.0.0` passa a ser esta rc.

---

## 1. Como esta rc é gerada

O fluxo é o de [MANUAL.md §3.3](../MANUAL.md#33-promoção-para-homologação), sem passo manual além do merge:

1. PR `develop` → `master`. O check `Origem do PR (master)` só aceita a `develop` como origem.
2. No merge, o `cd-homologacao.yml` calcula a versão a partir de `expo.version` (`1.0.0`) e da
   última rc (`rc.12`): sai **`v1.0.0-rc.13`**, versionCode **1000013**.
3. Gera o APK HML assinado, publica o backend HML e roda os 3 smoke tests.
4. Confere que a URL embutida no APK responde e cria a tag e a GitHub Release (pré-release)
   com o APK e o changelog desde a rc.12.

O APK instala **por cima** da rc.12: mesma chave de assinatura e versionCode maior.

**Ordem backend e app:** só o backend muda, e sem mudança de comportamento. O APK é gerado de
novo porque o pipeline sempre publica os dois; o código do app é o mesmo da rc.12.

**Se o pipeline falhar:** nenhuma tag é criada quando a falha é no APK ou no backend. A rc.12
continua sendo a última publicada, e o `alarme-cd.yml` abre a issue "CD vermelho" para a
`master`. Corrigir na `develop` e promover de novo; o número `rc.13` é reaproveitado.

**Rollback:** reinstalar o APK da rc.12 exige desinstalar (versionCode menor). O backend volta
para a revisão anterior do `saude-monitor-backend-hom` no Cloud Run.
